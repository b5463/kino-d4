# KINO Twin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build KINO Twin — a browser-based 3D digital twin + virtual KDP device at `apps/twin` — so a Studio developer with no physical camera can inspect a dimensionally sourced D4 V1 assembly, connect KINO Studio to the simulator over real KDP bytes, and exercise capture, faults, timing, power, gallery, Roll and firmware-update flows.

**Architecture:** Three new workspace packages plus one new app. `@kino/hardware-profiles` holds declarative, provenance-tagged D4 V1 hardware data (components, layout, nets, power). `@kino/simulator-engine` wraps the existing `MockKinoDevice` (which already speaks framed KDP from the device side) with a boot state machine, capture choreography, power/thermal/flash models, deterministic recording/replay, and a BroadcastChannel device server. `@kino/three-assets` builds parametric three.js proxies from profile data. `apps/twin` is a React 19 + React Three Fiber app rendering the scene and panels. Studio gains one new transport (`BroadcastTransport`, kind `'twin'`) — no fake-device special cases in feature code.

**Tech Stack:** TypeScript strict, npm workspaces, Node ≥22. Twin: React 19, Vite 6, three ^0.176, @react-three/fiber ^9, @react-three/drei ^10, zustand ^5. Contracts: zod via `@kino/schemas` `defineSchema`/`parseVersioned`. Tests: vitest (node environment; Node ≥18 provides global `BroadcastChannel`, so the cross-tab transport is unit-testable).

**Spec:** `kino_twin_spec/KINO_TWIN_SIMULATOR_SPEC.md` (cited as `§N`), plus `kino_twin_spec/component-manifest.json`, `kino_twin_spec/scene-layout.json`, `kino_twin_spec/SOURCES.md`. The platform context is `docs/superpowers/plans/2026-08-14-kino-platform-implementation.md` and `kino_dev_spec_pack/`.

## Global Constraints

Copied from the spec — every task's requirements implicitly include these:

- All geometry is stored in **millimetres**. `+X` = camera left-to-right viewed from front, `+Y` = up, `+Z` = toward subject. Origin = provisional enclosure geometric center (§4).
- Provisional body envelope **126 × 80 × 36 mm**, front plane ≈ `Z = +18`, rear ≈ `Z = -18` — PROVISIONAL until measured (§4).
- Camera pitch **20–24 mm adjustable, 22 mm default**; at 22 mm lens centers are X = −33, −11, +11, +33; the four camera nodes are children of one rigid camera-bar assembly (§5). Pitch is exposed as slider **and** exact numeric input.
- Every component dimension carries a provenance state (`MEASURED`, `OFFICIAL_CAD`, `OFFICIAL_SPEC`, `SELLER_SPEC`, `PROVISIONAL`, `CONFLICT`). When trustworthy sources conflict, store both and show `MEASURE TO LOCK` — never silently choose. Priority: MEASURED > OFFICIAL_CAD > OFFICIAL_SPEC > SELLER_SPEC > PROVISIONAL (§6).
- **Never hard-code an OV3660 FOV.** FOV fields are `null` + `fovConfidence: "MEASURE_REQUIRED"`; candidate lens FOVs (60/70/75/90/120°) are always labelled design scenarios (§7.3, §9).
- Battery rules: harness safe sustained **≤3 A**, very short pulse ≤6 A, preferred charge **600 mA**, max charge **1500 mA**. Never model 3 A / 1C charging as acceptable (§7.4, §15).
- Flash current presets **350 mA default / 500 mA experimental / 650 mA controlled-testing only**. Never present 1.5 A as a KINO recommendation (§7.10, §16).
- Twin speaks **raw KDP bytes** — no simulator JSON side-channel that bypasses protocol behavior. Studio pages never read Twin's internal state store. Fault propagation goes through KDP (§10, §20).
- Timing metrics stay separate: **GPIO distribution skew / VSYNC phase skew / effective exposure skew**. Simulated values are labelled **SIMULATED**, never presented as measured V1 hardware (§14).
- Every power number is tagged `MEASURED | MANUFACTURER | SELLER | ESTIMATED | SIMULATED` (§15).
- Core capture rule: **capture → SD first → camera ready → background upload**; no Roll/server condition may block simulated capture (§18).
- Replay must be **deterministic**; a bug report is one `.kino-sim.json` file + Replay (§21).
- A future KINO device should require a new hardware profile + 3D assets, not a rewrite of Twin or Studio (§25).
- Repo conventions: packages extend `tsconfig.base.json` (strict, `noUncheckedIndexedAccess`), `main`/`types` point at `src/index.ts`, scripts `test`=`vitest run`, `lint`=`tsc --noEmit`. Workspace globs `apps/*`, `packages/*` pick new workspaces up automatically.
- UI copy voice: blunt and functional, no flavor prose (project preference).

```ts
// packages/hardware-profiles/src/types.ts (shapes — full zod in implementation)
import { z } from 'zod';
import { defineSchema } from '@kino/schemas';

export const SOURCE_KINDS = ['MEASURED', 'OFFICIAL_CAD', 'OFFICIAL_SPEC', 'SELLER_SPEC', 'PROVISIONAL'] as const;
export type SourceKind = (typeof SOURCE_KINDS)[number];
export const PROVENANCE_TAGS = ['MEASURED', 'MANUFACTURER', 'SELLER', 'ESTIMATED', 'SIMULATED'] as const;
export type ProvenanceTag = (typeof PROVENANCE_TAGS)[number];

const mm3 = z.tuple([z.number().nullable(), z.number().nullable(), z.number().nullable()]);

export const dimensionSource = z.object({
  kind: z.enum(SOURCE_KINDS),
  sizeMm: mm3,               // [x, y, z] in scene axes; null = unknown axis
  ref: z.string().optional(),   // URL or SOURCES.md pointer
  note: z.string().optional(),
});
export type DimensionSource = z.infer<typeof dimensionSource>;

export const keepoutDef = z.object({
  id: z.string(), label: z.string(),
  sizeMm: z.tuple([z.number(), z.number(), z.number()]),
  offsetMm: z.tuple([z.number(), z.number(), z.number()]), // relative to component origin
  kind: z.enum(['connector', 'insertion', 'ejection', 'service', 'travel', 'clearance']),
});
export type KeepoutDef = z.infer<typeof keepoutDef>;

export const componentDef = z.object({
  id: z.string(), name: z.string(), model: z.string().optional(),
  qty: z.union([z.number().int().positive(), z.literal('as-needed')]),
  meshTier: z.enum(['A', 'B', 'C']),   // §22 fidelity tier
  sources: z.array(dimensionSource).min(1),
  specs: z.record(z.unknown()).optional(),
  keepouts: z.array(keepoutDef).default([]),
});
export type ComponentDef = z.infer<typeof componentDef>;

export const instanceDef = z.object({
  id: z.string(), component: z.string(),
  positionMm: z.tuple([z.number(), z.number(), z.number()]),
  rotationDeg: z.tuple([z.number(), z.number(), z.number()]),
  group: z.enum(['camera-bar', 'body', 'power', 'shell']).default('body'),
  explodeOrder: z.number().int().default(0),     // §8 exploded view: front acrylic=9 … rear acrylic=0
  explodeDirMm: z.tuple([z.number(), z.number(), z.number()]).default([0, 0, 1]),
});
export type InstanceDef = z.infer<typeof instanceDef>;

export const powerProfile = z.object({
  battery: z.object({
    nominalV: z.number(), capacitymAh: z.number(),
    internalOhm: z.object({ value: z.number(), tag: z.enum(PROVENANCE_TAGS) }),
    safeContinuousA: z.number(), shortPulseMaxA: z.number(),
    chargePreferredA: z.number(), chargeMaxA: z.number(),
  }),
  boost: z.object({ efficiency: z.object({ value: z.number(), tag: z.enum(PROVENANCE_TAGS) }) }),
  loads: z.record(z.object({ amps: z.number(), tag: z.enum(PROVENANCE_TAGS), note: z.string().optional() })),
  fuse: z.object({ ratingA: z.number(), type: z.literal('fast') }),
});
export type PowerProfile = z.infer<typeof powerProfile>;

export const hardwareProfile = defineSchema({
  schema: 'kino.hardware-profile',
  version: 1,
  shape: z.object({
    schema: z.literal('kino.hardware-profile'), version: z.literal(1),
    profile: z.string(), name: z.string(), units: z.literal('mm'),
    body: z.object({ sizeMm: z.tuple([z.number(), z.number(), z.number()]), confidence: z.enum(SOURCE_KINDS) }),
    cameraPitchMm: z.number(), cameraPitchRangeMm: z.tuple([z.number(), z.number()]),
    components: z.array(componentDef), instances: z.array(instanceDef),
    power: powerProfile,
  }),
  migrations: {},
});
export type HardwareProfile = z.infer<typeof hardwareProfile.shape>;
```

Camera-node specs include `"horizontalFovDeg": null, "verticalFovDeg": null, "fovConfidence": "MEASURE_REQUIRED", "resolution": [2048, 1536], "sensor": "OV3660"`. Keepouts (§7.1, §8): main-display gets both USB-C, TF slot, speaker/battery/camera connectors, 2×13 header; camera-node gets service-USB access; micro-sd gets ejection path; battery gets cushion/expansion clearance; speaker gets opening; tact-switch gets travel; flash-heatsink gets diffuser spacing.
